# ADR 0002: 地点別誤差図の位置軸に廊下弧長 s を採用し true_x を棄却する

- Status: Accepted
- Date: 2026-07-27

## Context

最終報告書の主張は「gp_corridor が LOLO 平均 0.72 m を達成し、WCL 系の凸包バイアスを
回避した」というものである。CDF 図は誤差の分布形しか示さないため、**どの位置で**
各手法が破綻するかを示す補助図として、位置を横軸・誤差を縦軸に取る図を追加した
（`scripts/plot_error_vs_s.py`、出力は `results/extra/`）。

初版ではこの位置軸に測量座標の `true_x`（`results/lolo_ledger.csv` の列）を用いた。
座標がそのまま台帳にあり変換が要らない、という実装上の都合による選択である。

しかし本学 C 棟 3F の廊下は **L 字**であり、`icsr8.corridor.CORRIDOR_SEGMENTS` が
定義する 3 区間のうち **C2 は x=0 に沿う縦棒区間**（y が 0→56 m）である。
したがって `true_x` は地点を一意に決めない。実測：

| true_x [m] | 該当地点数 |
|---|---|
| 0 | **29**（59 地点の約半数、held_out 17–45） |
| 28, 26, 24, 22, … | 各 2（C と C3 が同じ x 範囲を別の y で走るため） |

結果として、図の x=0 の位置に 29 地点分の誤差が縦一列に積み上がり、
「1 地点 = 1 点」という読み手の当然の期待が破れていた。折れ線が図上を往復するのを
避けるためセグメント境界で線を分断する回避策を入れていたが、これは**症状の隠蔽**で
あって、軸が地点を識別できないという原因は残ったままだった。

## Decision

1. 位置軸には **廊下弧長 s [m]**（`icsr8.corridor.xy_to_arclength(x, y)`、
   L 字を 1 本に伸ばした入口からの道のり、0–116 m）を用いる。
   検証：59 地点すべてが一意な s を持ち、かつ held_out 順（歩行経路順）に
   **単調増加**する。
2. `true_x` を位置軸として用いる案は**棄却**する。上記のとおり地点を識別できず、
   図が誤読を招くため。線の分断による回避策も同時に撤去した
   （s が単調なので 1 本の折れ線で正しく描ける）。
3. スクリプト名・関数名・出力ディレクトリを軸に合わせて改名する
   （`plot_error_vs_x.py` → `plot_error_vs_s.py`、
   `results/extra/error_vs_x/` → `results/extra/error_vs_s/`）。
   軸の意味とファイル名が食い違うと、同じ誤りが再発する。
4. 廊下セグメント（C / C2 / C3）は s 軸上の連続区間になるため、背景の濃淡帯で示す。

## Consequences

- 良: 1 地点 1 点が保証され、`results/extra/per_location_error.png`（held_out ID 軸）と
  同じ読み方ができる。さらに横軸が「何メートル歩いた地点か」という物理的意味を
  保つので、地点 ID より情報量が多い
- 良: gp_corridor の破綻箇所（C→C2 境界付近）が s 軸上の位置として特定でき、
  セグメント分類段（LogisticRegression）の誤分類という仮説に直接結びつく
- 良: セグメント境界での線分断という回避コードが不要になり、実装が単純化した
- 悪: 台帳（`lolo_ledger.csv`）は x/y しか持たないため、描画のたびに
  `xy_to_arclength` の変換が要る。59 地点 × 手法数の軽い計算なので許容する
- 中立: 本 ADR は `results/extra/` の補助図のみに関わる。ADR 0001 の凍結成果物
  （`cdf_lolo.pdf`・`segment_heatmap.pdf` 等）は一切変更していない
